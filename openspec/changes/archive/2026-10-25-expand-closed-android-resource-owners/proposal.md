# Expand the closed Android resource owner batch

## Why

SettingNetwork, SystemUI, BluetoothPhone and Media require independent exact process proofs. Recognizing their capability tuples must not publish unfinished data or make the existing Setting controls depend on a nonrunning owner.

## What Changes

- Recognize seven exact Android owners and fourteen exact A9/A11 resource tuples in the existing signed-delivery and probe machinery.
- Preserve two candidates per owner, signed-declared scope, independent Setting admission, all-owner inventory revocation and nonrunning-process waiting.
- Bound reversible cleanup to fourteen profiles and prove that late-member failures prevent any final commit.

## Impact

Shared owner tuples, fixed daemon event/worker slots, bootstrap classification tests and lifecycle tests. No agent metadata or Gradle publication, SELinux type/path/grant, QNX persistence, VM operation or firmware fingerprint gate.

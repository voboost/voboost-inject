## Why

CI fails at `make init` on a clean clone:

```
meson subprojects download
ERROR: wrap-redirect subprojects/frida-core/subprojects/libgee.wrap filename does not exist
make: *** [Makefile:37: init] Error 1
```

Seven `[wrap-redirect]` wraps are committed under `subprojects/`:
`libgee.wrap`, `libnice.wrap`, `libpsl.wrap`, `libsoup.wrap`, `quickjs.wrap`,
`tinycc.wrap`, `usrsctp.wrap`. Each is a `wrap-redirect` whose `filename` points
into a sibling subproject that is not yet fetched
(`frida-core/subprojects/libgee.wrap`, `frida-gum/subprojects/quickjs.wrap`,
`libsoup/subprojects/libpsl.wrap`, …). Meson resolves every redirect eagerly
while loading the wrap set — before any download — so on a clean clone the
target file does not exist and the command aborts.

Locally this is masked: `subprojects/frida-core/` is already fetched, so the
redirect target exists and `meson subprojects download` succeeds. CI clones from
scratch, so the target is absent and the build dies.

These wraps are transitive: `meson subprojects download` regenerates them
automatically from each parent wrap's `[provide]` section during `meson setup`.
The `subprojects/.gitignore` header even says so:

```
# Transitive .wrap files are auto-generated by `meson subprojects download`
# from the parent wraps' [wrap-redirect]/[provide] sections. Ignore them all
# and re-allow only the wraps we author and commit.
```

But the same `.gitignore` then re-allows the seven redirects
(`!libgee.wrap`, `!libnice.wrap`, …), and they were committed in `9a8e999`
(`feat(inject)`) and never removed. The archived change
`2026-06-28-fix-provisioning-wraps` described their removal in its tasks and
updated the `provisioning` spec to forbid redirect wraps, but the code fix was
never applied — the files remained in the tree, so the spec and the code
diverged. This change applies the fix the spec already demands.

## What Changes

- Remove the seven committed `[wrap-redirect]` wraps from `subprojects/`:
  `libgee.wrap`, `libnice.wrap`, `libpsl.wrap`, `libsoup.wrap`, `quickjs.wrap`,
  `tinycc.wrap`, `usrsctp.wrap`. They are regenerated by meson from the parent
  wraps' `[provide]` sections during `meson setup`.
- Fix `subprojects/.gitignore`: stop re-allowing the seven redirect wraps. Keep
  re-allowing only the wraps the project authors and commits: `frida.wrap`,
  `frida-core.wrap`, `frida-gum.wrap`, `monocypher.wrap`, `selinux.wrap` (the
  direct git wraps and the one override carrying a `patch_directory`).

## Capabilities

### Modified Capabilities
- `provisioning`: `subprojects/` wraps are clean-clone bootstrappable — no
  committed `[wrap-redirect]` whose target lives inside a not-yet-fetched
  subproject; `make init`'s `meson subprojects download` exits 0 on a clean
  clone. (Brings the code into compliance with the existing spec requirement
  "Subproject wraps are clean-clone bootstrappable".)

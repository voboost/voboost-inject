## ADDED Requirements

### Requirement: Fixture manifest covers integration-scenario target processes

The signed fixture manifest generated by `test/fixtures/gen-fixtures.sh` SHALL
declare an agent for every target process an integration scenario exercises,
so the daemon does not reject the scenario's plan as "unknown agent id". In
particular it SHALL include an agent for `com.qinggan.app.launcher` (the
`attach-launcher` scenario's target). The generator SHALL re-sign the manifest
and regenerate the manifest-embedding APK/release-manifest fixtures in the same
run, keeping them consistent.

#### Scenario: attach-launcher target has a fixture agent
- **WHEN** `gen-fixtures.sh` runs
- **THEN** the fixture manifest includes an agent whose `process` is
  `com.qinggan.app.launcher` (e.g. `launcher-echo`), with its payload file
  and sha256, and `manifest.sig` signs the resulting `manifest.json`

#### Scenario: Fixture manifest covers all scenario targets
- **WHEN** the integration suite's app-target scenarios are enumerated
  (launcher, vehiclesetting, system_server)
- **THEN** each has at least one agent in the fixture manifest, so no scenario
  is rejected for an unknown agent id

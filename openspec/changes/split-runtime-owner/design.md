# Design

The daemon is a generic native-agent host and the sole runtime state/config/file-log owner. FEV/PW policy remains in catalog-declared native agent executors. One logical agent can have native, Java and QNX executors. The source metadata generates the executor registry; no manually maintained vehicle-agent list or FEV/PW branches belong in the host.

Early startup verifies only its necessary native closure. The daemon verifies only its own native closure; it never verifies DEX on behalf of inject. Inject owns DEX/implant verification and process/ABI/probe/injection responsibility. Each component caches only its own verified immutable inputs. Full package verification runs on installation; heavy Java/resource verification is lazy before use and is reused within a daemon epoch. Persisted metadata alone does not establish unchanged file contents across boots. Optional kernel-backed integrity requires demonstrated capabilities; it is not presumed. Logger history reconstruction is outside native-agent startup dependencies.

Implementation is in progress. The two executable targets, private owner storage, bounded native-peer IPC and inject state/configuration/journal clients exist in source. Native and app log writes and status publication use the owner; session archive export is integrated. Log retention, live query consumers, remaining lifecycle publications, packaged process separation and native execution are not accepted. See the workspace plan 2026-10-29-07-35-daemon-native-agents-and-verification-cache-design.ru.md for measured-source facts, ownership and cache boundaries. No persistent verification-cache admission is implemented.

This pre-release split does not migrate journals or preserve compatibility with the previous combined daemon. Reinstallation and reapplying vehicle settings are acceptable. Read only the current journal format and location; do not adopt or reconcile previous journal files. Durable OFF ordering and crash recovery within the current version remain required.

Cold startup reads no log archive, sequence checkpoint or historical batch ledger. A new writer session creates a new file and session-scoped sequence; archive reads and retention do not gate native startup. Query/cursor/dedup consumers require coordinated contract updates before this logging redesign is shipped.

Retention runs after startup and shares the append/export snapshot lock. Native segments and committed app-batch tier files share independent 128 MiB debug/info/error budgets. A durable retirement marker precedes removal of a batch tier; readers skip only explicitly retired tiers, and retries never recreate them. Missing files without retirement remain an error. Active native segments are protected. Pending batches retain their bounded recovery material. Receipt admission is separately bounded to 32 MiB and 4096 identities; reaching either bound rejects a new identity before staging its events, while an existing confirmed identity remains retryable. Receipt inventory is metadata-only and lazy on admission, never a boot prerequisite. These bounds intentionally prefer an explicit unavailable result over discarding deduplication authority or unbounded disk growth. They require runtime capacity/latency acceptance before release.
